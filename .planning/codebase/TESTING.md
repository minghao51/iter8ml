# Testing Conventions

## Test Framework

- **pytest** (`>=9.0.3`) with `pytest-cov` for coverage
- Config in `pyproject.toml:118-130`
- Run via `uv run pytest` (never bare `pytest`)

## Directory Layout

```
tests/
├── conftest.py              # Session-scoped fixtures (classification_data, regression_data, tmp_workspace)
├── unit/                    # Fast, isolated tests (no heavy ML, no external services)
│   ├── test_adapter.py
│   ├── test_baselines.py
│   ├── test_cli.py
│   ├── test_config.py
│   ├── test_drift.py
│   ├── test_evaluator.py
│   ├── test_exceptions.py
│   ├── test_hpo_unit.py
│   └── ... (40+ files)
├── integration/             # Full pipeline, real model training
│   ├── conftest.py          # large_classification_data (session scope)
│   ├── test_full_pipeline.py
│   ├── test_gdbt_models.py
│   ├── test_hpo.py
│   └── test_model_selection.py
└── e2e/                     # Critical path smoke tests
    ├── .gitkeep
    └── test_smoke.py        # @pytest.mark.smoke
```

- Mirrors `src/iter8ml/` structure but flattened (no subdirectory nesting)
- `pythonpath = ["src"]` enables `import iter8ml` directly
- `--import-mode=importlib` avoids conftest namespace conflicts

## Marker/Tag Usage

Defined in `pyproject.toml:122-130`:
| Marker | Applied By | Usage |
|---|---|---|
| `unit` | Auto in `conftest.py:28` for `tests/unit/*` | Fast isolated tests |
| `integration` | Auto in `conftest.py:32` for `tests/integration/*` | Heavy/full pipeline |
| `e2e` | Auto in `conftest.py:35` for `tests/e2e/*` | Full workflow |
| `slow` | Auto with integration/e2e | >1s tests |
| `smoke` | Manual (`tests/e2e/test_smoke.py:12`) | Critical path |
| `serial` | Manual | Cannot parallelize |
| `network` | Manual (`test_model_selection.py:33`) | Needs internet/auth |

- Auto-annotation via `pytest_collection_modifyitems` hook in `tests/conftest.py:27`
- `--strict-markers` enabled (unknown markers cause errors)
- `-ra` shows all failures summary
- `--durations=10` shows 10 slowest tests

## Fixture Patterns

- **Shared fixtures** in `tests/conftest.py`:
  - `classification_data` (session scope) — 500 rows, 10 features
  - `regression_data` (session scope) — 500 rows, 10 features
  - `tmp_workspace` (function scope) — tmp_path-based workspace directory
- **Integration fixtures** in `tests/integration/conftest.py`:
  - `large_classification_data` (session scope) — 15000 rows, 20 features
- **Local fixtures** defined per test file when needed (e.g., `sample_csv`, `sample_parquet` in `test_cli.py`)
- No complex fixture chains — fixtures are self-contained
- Prefer `tmp_path` built-in over `tempfile.TemporaryDirectory()` where possible

## Mocking Approach

- Uses `unittest.mock.Mock()` for lightweight mocking (`test_hpo_unit.py:155`)
- Uses `monkeypatch` fixture for replacing module-level functions (`test_hpo_unit.py:213`)
- Dummy model classes defined inline in test files (`DummyModel`, `DummyTracker`, `DummyTrainer`)
- Mock objects track call history via `side_effect` for simulating failures
- CLI tests use `typer.testing.CliRunner.invoke()` — avoids mocking the CLI framework itself
- No `pytest-mock` dependency — uses stdlib `unittest.mock` and builtin `monkeypatch`

## Test Patterns by Type

### Unit Tests (most common pattern)
```python
"""Docstring describing what's being tested."""
import pytest
from iter8ml.module import thing

def test_scenario_description():
    result = thing(args)
    assert result == expected
```

### Error path tests
```python
def test_error_condition():
    with pytest.raises(SomeError, match="expected message"):
        thing(bad_args)
```

### CLI tests
```python
from typer.testing import CliRunner
from iter8ml.cli import app

runner = CliRunner()

def test_command():
    result = runner.invoke(app, ["command", "--flag", "val"])
    assert result.exit_code == 0
    assert "expected output" in result.stdout
```

### Class-based test organization
```python
class TestComponent:
    @pytest.fixture
    def data(self):
        return make_data()

    def test_behavior_a(self, data):
        ...
```

## CI Test Execution

- `uv run pytest tests/unit -v` for unit tests (fast, run on every change)
- `uv run pytest tests/integration -v` for integration tests
- `uv run pytest` runs all test paths
- `--strict-markers` catches typos in marker names
- `-ra` ensures no failures go unnoticed
- `--durations=10` helps identify slow tests
- Pre-commit runs `ruff check --fix`, `ruff-format`, and `uv run mypy .` (not tests/)

## Coverage Configuration

Defined in `pyproject.toml` via pytest-cov, but no explicit `[tool.coverage.*]` section found. Coverage reports to `.coverage` and `htmlcov/` (gitignored).

## Key Testing Conventions

1. **No real external services** — unit tests use dummy data generated by sklearn
2. **Deterministic randomness** — `random_state=42` throughout
3. **Temp directories** via `tmp_path` fixture or `tempfile.TemporaryDirectory`
4. **CLI tests** use `CliRunner` (not subprocess)
5. **`pytest.raises`** with `match=` for error assertions
6. **Clean test isolation** — each test creates its own data
7. **Docstrings on test functions** — but optional for simple cases
8. **No `__init__.py` files needed** in test directories (namespace packages, `--import-mode=importlib`)
